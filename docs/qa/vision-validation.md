# 視覺辨識修正目標與驗證

## 目標與實作順序

1. 曝光／場景：以中位亮度差補償曝光，排除大片變動；連續穩定影格後才產生候選，不把未分類變動混入背景。
2. 校正：依 cropRect 與 rotationDegrees 取樣、保持長寬比及畫面上下方向。要求多條同心環與外圈支持，僅接受接近正面的單靶面；三靶面停用自動辨識，使用手動輸入。辨識期間固定校正，需重新校正時由使用者操作。
3. 箭點：移除必須延伸到外圈的條件，沿連通區主軸找端點；方向不明的對稱箭影拒判。端點選擇仍是單鏡頭幾何假設，不是可靠箭尖識別，信心分數最高 0.65，必須人工確認。
4. 記錄：只在資料庫記錄成功後接受新背景；拒絕或失敗時保留舊背景並暫停辨識。事件回覆只接受一次，舊事件不能完成新事件。移除以距離排除合法密集箭群的邏輯。
5. 回歸：先執行九個視覺測試，再加入三個記錄確認測試；最後集中執行一次建置、全套單元測試與 Lint。

## 驗收命令

```sh
bash gradlew --no-daemon --max-workers=4 assembleDebug testDebugUnitTest lintDebug
```

合成測試包含曝光下降、大片陰影、中央短箭影、穿越靶心的對稱箭影、越界取樣、有效同心環、單一圓邊界拒判、旋轉映射、場景穩定度與記錄確認。這些測試不代表戶外準確率。

## 必須保留的限制

- 斜拍透視、三靶面與部分靶面遮擋不宣稱支援自動校正。
- 相機移位後應重新校正；目前沒有完整的影像配準或透視追蹤。
- 單鏡頭箭桿投影無法普遍決定入靶端點，所有自動箭點仍需人工確認。
- 尚無帶真實落點標註的實拍資料集，因此無法給出漏判率、誤判率或毫米級精度。
- 實場驗收應涵蓋晴天／陰影／曝光變動、相機微震、密集箭群、不同靶紙與距離，且以未參與調參的資料評估。

## 執行結果

- 九個視覺案例先獨立通過。
- 首次整體檢查：Debug APK、18 個單元測試與 Lint 全部通過。
- 最後審查發現「已同步後的刪箭」與「等待資料庫記錄同步」需區分，新增三個邊界案例。只重跑受影響的六個 PendingShotCommitTest，並重新建置與 Lint；未重跑無關的模擬器驗收。
- 三靶面、透視校正及可信箭尖識別仍屬未支援能力；此修正採保守拒判／人工確認，不能宣稱已完成通用視覺辨識。
